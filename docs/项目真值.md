## 5.5 前端构建强制规则 ⚠️

**修改 `frontend/src/` 下任何文件后，必须重新构建才能生效。**

| 场景 | 必须执行的命令 |
|------|---------------|
| 修改前端代码后 | `cd frontend && npm run build` |
| 使用启动脚本 | `scripts/启动.bat`（已自动构建） |
| 使用 `python start.py` | 需手动构建前端，或改用 `启动.bat` |

**为什么**：后端 SPA fallback 直接服务 `frontend/dist/` 的静态文件。源码修改不会自动同步到 dist，必须手动构建。

**验证方法**：构建后检查 `frontend/dist/index.html` 是否存在且时间戳为最新。

### 从经验 #003 固化: 编辑了老版本文件而非当前产品代码


- **关键教训**: > **`.html` 文件存在 ≠ 它就是用户看到的东西。**
>
> 项目有两套前端时——一套 raw HTML（v2 原型），一套 React SPA（v3 当前产品）——
> AI 必须主动验证哪个是用户的真实入口。验证方法：
> 1. 读 `api_server.py` → 找 `StaticFiles`、`mount`、`SPA fallback`
> 2. 检查 `frontend/dist/` 构建时间 vs `app/rag_app/web/` 修改时间
> 3. 如果两个都新鲜，以 SPA fallback 为准（React build 优先）
>
> **先跑通整条链路，再改文件。否则改再多都是白忙。**
- **改进措施**: **改前端前必须先读 api_server.py**，确认静态文件挂载路径和 SPA fallback 顺序
- **改进措施**: **接手时检查多套前端并存**：优先按构建产物时间判断活跃版本
- **改进措施**: **「版本号只升不降」扩展**：改了文件后必须验证文件确实属于当前活跃版本 (VERSION.md)
- **改进措施**: **新增标签 `#老版文件`** (本篇经验标签索引)
