## 四、当前读法

### 已收口：`S0-04` 删除闭环判定

- **结果**：当前不补真删除，先把假成功改成 `501` 诚实占位。
- **理由**：它不是当前 M0/M1 过线所必需，但不能继续用误导性成功响应污染真值。
- **后续位置**：正式删除闭环停放到 `post-M1` support slice。

### 当前第一刀：`S1-01` 图谱数据契约

- **为什么现在做**：它能把 L2 第一段从“想做图谱”变成“先定数据结构和接口边界”。
- **建议动作**：先出最小字段集和一个样例 payload，不急着写完整图谱实现。
- **完成标志**：后端、前端、后续 GLM 都能用同一份契约开工。

### 当前第二刀：`S1-02` 只读图谱 API

- **为什么接着做**：现在字段和样例都已固定，最自然的下一步就是把样例通过正式路由读出来。
- **建议动作**：先做最小 `GET /api/graph/data`，只返回样例或当前文件，不急着接真实提取链。
- **完成标志**：本地请求能返回符合契约的合法 JSON。

### 当前第三刀：`S1-03` 规则优先概念提取最小版

- **为什么现在轮到它**：只读 API 已有正式消费面，下一步要开始让图谱摆脱纯样例数据。
- **建议动作**：先从标题、关键词、固定规则中抽概念与关系，不急着引入复杂 LLM 推理。
- **完成标志**：给定一个受控样本文件，能产出符合契约的 `nodes/edges`。

### 当前第四刀：`S1-04` `graph.html` 只读展示页

- **为什么现在轮到它**：契约、样例路由和规则提取都已有最小消费面，前端终于可以对真实图谱结构做只读验证。
- **实际收口**：已补 `rag_app/web/graph.html`，并通过共享 `app.js` 消费 `/api/graph/data` 与 `/api/graph/extract`；当前页面支持样例加载、规则提取演示、节点/边可视化与基础详情查看。
- **完成标志**：页面已可消费 `/api/graph/data` 与 `/api/graph/extract` 的结果，并可见节点与边。

### 当前第五刀：`S2-01` 概念串联与缺口提示最小契约

- **为什么现在轮到它**：图谱链已经有契约、样例、提取和只读展示，下一步更值得先定义“如何返回串联链和缺口提示”，避免后面直接在智能层自由发挥。
- **实际收口**：已新增 `docs/contracts/knowledge-views/概念串联与缺口提示契约.md` 与 `output/graph/graph-chain-sample.v1.json`，并已把 `/api/graph/chain` 推到 rule-backed 最小链；`graph.html` 也已接上 chain/gap 面板，能展示当前最小串联链与缺口提示。2026-05-08 先补到 `auto/live/sample` 三态，随后又补了 `compact/balanced/wide` 三档 live 选材 profile，再补上 `focus_concept` 聚焦路径；本轮进一步补出 `relevance / recency / diversity` 三档排序策略，backend 与页面都已能回显当前排序面。
- **当前完成标志**：`/api/graph/chain` 现已能返回至少 1 条 `related_chain` 与 1 条 `gap_hints`；sample 模式下 `meta.source_mode=rule-backed-sample-graph-data`，live 模式下 `meta.source_mode=rule-backed-live-knowledge-base`，并会回显 `selection_profile / sorting_strategy / selected_chunk_count / available_chunk_count / focus_result`。`tests/smoke_test.py` 当前为 `51/51 PASS`。
- **下一刀**：如果继续沿图谱线收窄，更适合做解释性细化与权重透明；如果转到更通用的产品能力，下一片更适合正式打开 `S2-02 分析总结` 最小契约。

### 当前第六刀：`S2-02` 分析总结最小契约与最小接口

- **为什么现在轮到它**：`S2-01` 的最小可控闭环已经过线，再继续细抠图谱控制面收益递减；而 `S2-02` 能把“更通用的产品能力”先切成一条薄闭环。
- **实际收口**：已新增 `docs/contracts/analysis/分析总结契约.md`，并补出 `POST /api/analysis/summary` 最小接口；当前先支持 **已索引文件集合** 的结构化摘要，诚实边界是不直接冒充真实文件夹分析器。
- **当前完成标志**：响应已固定 `title / summary / highlights / selected_files / meta` 结构；当 LLM 不可用时，会回退到 `extractive-fallback-indexed-scope`，不假装“分析失败就没有结果”。
- **下一刀**：优先把这条接口接进最小前端入口，或补多文件主题提炼；不适合直接跳深度报告系统。
