# PRD：图谱提取管线升级（LLM-first 渐进替换）

> **版本**：v1.0 | **日期**：2026-07-21 | **作者**：产品通（PM）

---

## 问题陈述

当前图谱提取管线基于纯规则（jieba 分词 + 正则模式），导致两个核心问题：

1. **节点质量差**：按词频选 top-N，对话碎片（"怎么说也"、"回来"）频率远高于人物名，选出的节点无意义
2. **边无语义**：`_build_edges` 序列边 fallback，label 全是 `A…B` 或同句标记，无法推理

对比测试证明：LLM 提取出"陈异、苗靖、藤城"等真实实体，规则提取出"怎么说也、异身上能"碎片。

**业务影响**：知识图谱是产品的核心差异化功能，但当前图谱基本不可用——用户问"苗靖和陈异什么关系"时，图谱里根本找不到这两个人。

---

## 方案：LLM-first 渐进替换

### 核心原则
- 保留规则提取做 fallback（API 挂了系统不崩）
- 新增 LLM 提取管线（NER + RE），用 DeepSeek API
- 渐进替换，每步可回退

### 管线设计

```
chunk 文本 → LLM 提取（NER + RE）→ 结构化图谱 → JSON 缓存
                ↓（API 失败时）
          规则提取（简化版，只出节点不出边）
```

### LLM Prompt 设计

```
请从以下文本中提取知识图谱信息。
要求：
1. 识别最重要的实体（人物、地点、概念），不超过6个
2. 识别实体之间的关系，用中文表示（如"恋人"、"同事"、"居住地"）
3. 只返回 JSON：{"nodes": [{"label": "...", "category": "..."}], "edges": [{"from": "...", "to": "...", "label": "..."}]}

文本：{chunk_text}
```

### 成本控制

- 每次提取最多 6 节点 / 8 边，限制 prompt 长度
- 缓存结果到 JSON，相同 chunk 不重复调用
- 全库重建估算：8 篇 × 50 chunks × 500 tokens = 4 万 tokens ≈ 0.01 元

---

## 非目标（Non-Goals）

| 不做 | 理由 |
|------|------|
| 本地部署 LLM（OneKE 13B） | 显存不够，DeepSeek API 已够用 |
| 实时图谱 | 批量预提取 + JSON 缓存 |
| 100 页+长文档全量 | 限制 chunk 数，先跑通再扩 |
| 知识图谱持久化到 SQLite | JSON 文件足够，后续再升级 |

---

## 用户故事

| 角色 | 需求 | 价值 |
|------|------|------|
| 用户 | 打开图谱，看到"苗靖、陈异、藤城"等人物节点 | 图谱真正反映文档内容 |
| 用户 | 看到"同居、居住、拥有"等关系边 | 能推理人物关系 |
| 用户 | 问"苗靖和陈异什么关系"得到准确回答 | Q&A 基于图谱路径而非碎片 |

## 实施计划（渐进替换）

### Step 1：新增 LLM 提取管线（本周）
- 新增 `app/rag_app/llm_graph_extractor.py`
- 保留现有 `concept_extractor.py` 做 fallback
- 规则 fallback 时降级：只出节点不出边
- 验证：野狗骨头、原则、三体各跑一次对比

### Step 2：接入图谱路由（本周）
- `routes/graph.py` 调用顺序：LLM → fallback → 规则
- 验证：浏览器打开图谱，确认节点是人物而非碎片

### Step 3：接入 Q&A 检索（下周）
- `rag_engine.py` 的 `_build_graph_context` 改用新管线
- 验证：问"苗靖和陈异感情"能沿图谱路径推理

### Step 4：缓存 + 优化（下周）
- JSON 缓存到 output/graph/llm/
- 全库重建脚本

## 验收标准

| 指标 | 基线（当前规则） | 目标（LLM 提取） |
|------|----------------|-----------------|
| 节点质量（人物名占比） | ~20%（大量碎片） | ≥80% |
| 边语义（有中文标签） | ~10% | ≥70% |
| 野狗骨头图谱可识别主要人物 | 否 | 是 |
| API 不可用时系统不崩 | 是 | 是 |

---

## 风险

| 风险 | 应对 |
|------|------|
| LLM API 超时/失败 | 规则 fallback，降级为简化模式 |
| LLM 提取结果不稳定 | temperature=0.1，限制 max_tokens，JSON 解析失败时 retry |
| 长文档 token 超限 | 限制 chunk 长度，分批提取后合并 |
| 规则提取下线后老图失效 | 渐进替换，老图保留做对照 |
