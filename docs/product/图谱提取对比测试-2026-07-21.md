# 图谱提取：规则 vs LLM 对比测试

> **日期**：2026-07-21 | **测试对象**：野狗骨头 2000 字样本 | **结论**：LLM 全面胜出

---

## 测试数据

| 维度 | 规则提取 | LLM 提取 |
|------|---------|---------|
| **节点** | 怎么说也、异身上能、十分钟开、回来 | 陈异、苗靖、藤城、旧铁门、十分钟开锁 |
| **边** | A…B 序列标记 | 同居、居住、拥有、使用 |
| **doc_type** | 无分类 | 人物/地点/概念 |
| **tokens 开销** | 0 | ~500 tokens/1000字 |

---

## 根因分析

规则提取的核心缺陷——**按词频选 top-N，而对话碎片频率远高于人物名**。

```
小说文本中：
"回来" 出现 5 次   ← 词频高，被选中
"苗靖" 出现 3 次   ← 词频低，被淘汰

但"回来"是动词/副词碎片，不是人物。
```

LLM 的优势——**理解语义，而不是统计词频**。它能识别"苗靖"是人物名、"藤城"是地名、"同居"是关系。

---

## 结论

继续用规则提取做图谱是死路一条。规则提取做辅助（降本）可以，但主导提取必须用 LLM。

---

## 建议管线

```
chunk 文本 → LLM 提取（NER + RE）→ 结构化图谱 → 缓存
                ↑
          规则提取做 fallback（API 不可用时）
```

**成本估算**：8 篇文档 × 50 chunks × ~500 tokens = ~4 万 tokens ≈ DeepSeek API ~0.01 元/次全库重建。完全可接受。

**Non-goals**：
- 不做本地模型（需要 13B 显存）
- 不做实时图谱（批量预提取 + 缓存）
