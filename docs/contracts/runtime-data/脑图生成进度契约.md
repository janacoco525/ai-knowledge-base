# AI知识库 — 脑图生成进度契约

> **用途**：固定「长文档脑图生成进度查询」的最小输入、输出和诚实边界
> **更新日期**：2026-08-20
> **性质**：当前项目专用 Owner，配套 `GET /api/gemini/mindmap/progress`

---

## 一、这份契约先解决什么

- 长文档（2-10 万字）脑图生成需拆成最多 48 章任务、每章一次 LLM 调用（约 30s），
  6 并发全量生成需 3-5 分钟。新电脑无缓存首次生成更久。
- 此前前端只有 180s 硬超时无进度反馈 → 用户以为"卡死"。
- 本契约固定一个**进度查询端点**，让前端轮询显示"第 N/M 章（pct%）"。
- 当前只承接**脑图生成任务的内存进度查询**，不冒充通用任务队列系统。

---

## 二、当前范围边界

### 当前支持

- 按 `file_id` 查询某个脑图生成任务的实时进度（阶段/总数/已完成/百分比）
- 已完成任务的惰性清理（finished 后 120s 删除注册表条目，防无限增长）
- 短文档/缓存命中时不注册进度，查询返回空（前端轮询最多跑 1 次即停）

### 当前不冒充已有

- 不做通用任务队列（无持久化，进程重启进度丢失）
- 不做进度取消/中断控制
- 不做跨进程/多实例进度共享（模块级内存注册表，单进程）

---

## 三、数据存储契约

### 存储方案

模块级内存注册表：`app/rag_app/routes/llm_ops.py` 的 `_MINDMAP_PROGRESS: dict[str, dict]`，
配 `_MINDMAP_PROGRESS_LOCK`（threading.Lock）保证线程安全。

### 进度条目结构

| 字段 | 类型 | 说明 |
|------|------|------|
| `phase` | `string` | 阶段：`structure`（分析结构）/ `chapters`（分章生成）/ `done`（完成） |
| `total` | `number` | 章节任务总数（structure 阶段为 0） |
| `done` | `number` | 已完成章节数（无论成败都推进） |
| `current` | `string` | 当前正在处理的章节标题（≤40 字） |
| `started_at` | `number` | 任务开始时间戳（time.time()） |
| `finished` | `bool` | 是否已结束（成功/回退分支都会置 True） |

> key = `fileId or title`。**所有提前返回分支必须标记 `finished=True`**，
> 否则前端轮询永远停在"分析文档结构"。

---

## 四、请求/响应契约

### 4.1 查询脑图生成进度

**Endpoint**：`GET /api/gemini/mindmap/progress`

**Query 参数**：

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `file_id` | `string` | 否 | 空 | 文档 fileId（或 title）；空则返回空进度 |

**Response JSON（进行中）**：

```json
{
  "phase": "chapters",
  "total": 12,
  "done": 5,
  "current": "第6章 注意力机制",
  "started_at": 1755676800.123,
  "finished": false,
  "running": true,
  "pct": 41
}
```

**Response JSON（空/未注册/已清理）**：

```json
{
  "running": false,
  "phase": "",
  "total": 0,
  "done": 0,
  "current": "",
  "pct": 0,
  "finished": false
}
```

### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `running` | `bool` | `not finished`；前端据此决定是否继续轮询 |
| `pct` | `number` | `int(done/total*100)`，total=0 时为 0 |
| `finished` | `bool` | 任务是否结束；`true` 时前端停止轮询 |

## 五、前端轮询约定

- 轮询间隔 **2.5s**（`GraphPanel.tsx` 的 `setInterval`），生成期间启动、`finally` 清理。
- 对标主流长任务进度做法：暴露 GET 进度端点 + 前端固定间隔轮询 + 200 返回全状态。
  - 阿里云百炼图像/视频生成：长任务建议每 3-5 秒轮询直到非 RUNNING
    https://www.alibabacloud.com/help/zh/model-studio/first-call-to-image-and-video-api
  - 长任务进度 UI 模式：用户主动观看时 2-5 秒轮询为宜
    https://appmaster.io/es/blog/tareas-segundo-plano-progreso-patrones-ui
- 主请求超时放宽到 **600s**（原 180s 会掐断 3-5 分钟的全量生成）。
- 缓存命中时主请求秒回，轮询最多跑 1 次，无感停止。

---

## 六、最小验收

1. `GET /api/gemini/mindmap/progress`（无 file_id）返回空进度（running=false）
2. 未注册 file_id 返回空进度
3. 已注册进行中任务返回 running=true + 正确 pct
4. 完成态返回 finished=true、running=false
5. 所有提前返回分支（无章节/无任务回退）都置 finished=true
6. 前端能据 `done/total` 显示"第 N/M 章（pct%）"
7. 不把"内存进度注册表"误报成"通用任务队列系统"
