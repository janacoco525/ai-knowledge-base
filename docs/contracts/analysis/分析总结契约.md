# AI知识库 — 分析总结契约

> **用途**：固定 `S2-02 分析总结` 的最小输入、输出和诚实边界
> **更新日期**：2026-05-08
> **性质**：当前项目专用 Owner，不替代 `PRD` 与长需求清单

---

## 一、这份契约先解决什么

- 先让 `S2-02` 从“想做分析总结”变成一条可开工、可验证、可交接的最小闭环。
- 当前只承接 **已索引内容范围** 的摘要，不冒充完整文件夹分析系统。
- 当前最小接口定为：`POST /api/analysis/summary`

---

## 二、当前范围边界

### 当前支持

- 按 `file_ids` 对 1 到多个 **已索引文件** 做结构化摘要
- 按 `domain` 对一个 **已索引知识域** 做最小摘要
- 输出统一结构：`title / summary / highlights / selected_files / meta`

### 当前不冒充已有

- 不直接吃任意本地文件路径
- 不直接吃任意本地文件夹路径
- 不把“知识域范围摘要”说成“真实文件夹摘要”
- 不把最小摘要接口说成深度分析、AI Diff 或完整阅读报告

---

## 三、请求契约

### Endpoint

`POST /api/analysis/summary`

### Request JSON

```json
{
  "file_ids": ["example.md"],
  "domain": "ai_knowledge",
  "max_files": 3,
  "max_chunks_per_file": 3,
  "max_highlights": 4,
  "analysis_focus": "summary"
}
```

### 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `file_ids` | `string[]` | 否 | 来自 `GET /api/kb/files` 的已索引文件 ID |
| `domain` | `string` | 否 | 可选知识域筛选 |
| `max_files` | `number` | 否 | 当未显式指定足够 `file_ids` 时，最多抓取多少个文件 |
| `max_chunks_per_file` | `number` | 否 | 每个文件最多取多少个 chunks 参与总结 |
| `max_highlights` | `number` | 否 | 最多返回多少条 highlights |
| `analysis_focus` | `"summary" \| "topics" \| "risks"` | 否 | 当前总结关注面 |

---

## 四、响应契约

### Response JSON

```json
{
  "title": "Transformer.md 摘要",
  "summary": "……",
  "highlights": ["……", "……"],
  "selected_files": [
    {
      "id": "Transformer.md",
      "name": "Transformer.md",
      "domain": "ai_knowledge",
      "uploaded_at": "2026-05-08T10:00:00",
      "selected_chunk_count": 3,
      "available_chunk_count": 8
    }
  ],
  "meta": {
    "source_mode": "llm-backed-indexed-scope",
    "analysis_focus": "summary",
    "scope_mode": "file_ids",
    "available_file_count": 1,
    "selected_file_count": 1,
    "selected_chunk_count": 3
  }
}
```

### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `title` | `string` | 当前摘要标题 |
| `summary` | `string` | 当前范围的最小结构化摘要 |
| `highlights` | `string[]` | 从已索引 chunks 提炼出的短要点 |
| `selected_files` | `object[]` | 当前实际参与总结的文件集合 |
| `meta.source_mode` | `string` | `llm-backed-indexed-scope` 或 `extractive-fallback-indexed-scope` |
| `meta.analysis_focus` | `string` | 当前分析关注面 |
| `meta.scope_mode` | `string` | 当前范围来自 `file_ids / domain / recent` |

---

## 五、最小验收

1. `POST /api/analysis/summary` 对 1 个已索引文件返回 `200`
2. 响应中存在 `title / summary / highlights / selected_files / meta`
3. `selected_files` 与请求范围对得上
4. 当 LLM 不可用时，仍会回退成诚实的 `extractive-fallback-indexed-scope`
5. 不把知识域摘要误报成“真实文件夹摘要”

---

## 六、当前后续读法

- 这份契约落下后，`S2-02` 就不再是纯停放态，而是正式进入 **最小契约 + 最小接口** 阶段。
- 下一刀更适合做：
  - 把这条接口接进最小前端入口
  - 或增加“多文件主题提炼”的轻验证
- 不适合立刻跳到：
  - 深度报告系统
  - 完整文件夹分析器
  - AI Diff 混合面板
