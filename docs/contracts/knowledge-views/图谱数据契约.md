# AI知识库 — 图谱数据契约 v1

> **用途**：定义 `S1-01` 的最小图谱数据结构，供 `GET /api/graph/data`、`POST /api/graph/extract`、React 图谱组件和概念提取链共用
> **更新日期**：2026-05-12
> **性质**：图谱 payload 形状的当前 Owner；旧 `rag_app/web/graph.html` 仅作历史阶段参考

---

## 一、这份契约解决什么问题

`AI知识库` 的图谱是当前最重要的差异化能力。当前已经从早期静态 `graph.html` 阶段进入 React SPA + 后端图谱 API 阶段，因此必须持续把“图谱数据到底长什么样”说清楚。

这份契约的作用只有 3 个：

1. 统一后端输出和前端消费的最小字段集。
2. 把“概念提取”和“图谱展示”之间的接口固定下来。
3. 让后续模型或人工接手时，不用再各自发明一套 `nodes/edges` 结构。

---

## 二、当前边界

这份 v1 契约只负责 **最小可读图谱**，不负责完整智能图谱。

### 这次要做

- 定义最小响应包络
- 定义 `nodes` 和 `edges` 的必填字段
- 定义图谱样例 payload
- 定义 v1 的存放位置与验证方式

### 这次明确不做

- 不在本契约中实现真实 `graph` API 逻辑
- 不做真实概念提取算法
- 不做增量更新
- 不做 SQLite/Neo4j 迁移
- 不做复杂筛选、布局或分析字段

---

## 三、当前存放读法

为了让 `S1-02` 和 `S1-04` 有可对照样例，v1 先采用最轻方案：

| 对象 | 当前路径 | 读法 |
|------|------|------|
| 契约 Owner | `docs/contracts/knowledge-views/图谱数据契约.md` | 图谱字段定义以这里为准 |
| 样例 payload | `output/graph/graph-data-sample.v1.json` | 供 API 与前端对照开发 |
| 当前只读 API | `/api/graph/data` | 返回样例或知识库规则图谱 |
| 当前提取 API | `/api/graph/extract` | 从文本/文件提取最小图谱 |
| 预热 API（T11） | `POST /api/graph/prewarm` | 后台预热 live 图谱缓存，立即返回 `{"status":"started"}`，不阻塞 |

### `force_llm` 参数（2026-08-12）

`GET /api/graph/data?force_llm=1`：跳过缓存并强制 LLM 重新提取（降级后自救入口，对应前端"重试 LLM"按钮）。
降级（rules-fallback）结果仅短缓存 60 秒，避免坏图黏 10 分钟；`force_llm=1` 时不写缓存（保证重试真的重试）。
| 当前前端组件 | `frontend/src/components/KnowledgeGraph.tsx` | 图谱展示与交互 |

后续如果图谱生成变成稳定运行链，再决定是否升级到 `data/graph/` 或 SQLite；当前不要提前做重存储壳。

## 四、响应包络

`GET /api/graph/data` 的最小响应统一长这样：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `version` | string | 是 | 当前契约版本，固定为 `graph-data.v1` |
| `generated_at` | string | 是 | ISO 时间戳 |
| `source` | object | 是 | 本次图谱来源摘要 |
| `nodes` | array | 是 | 概念节点数组 |
| `edges` | array | 是 | 关系边数组 |
| `meta` | object | 是 | 给前端和调试看的附加信息 |

### `source` 字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `domain` | string | 是 | 当前图谱对应知识域；无筛选时用 `all` |
| `file_count` | number | 是 | 参与图谱的文件数 |
| `chunk_count` | number | 是 | 参与图谱的文本块数 |
| `extractor_mode` | string | 是 | 当前提取模式；v1 固定 `rules-first` |

### `meta` 字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `layout_hint` | string | 是 | 前端布局提示；v1 固定 `force-network` |
| `graph_title` | string | 是 | 页面默认标题 |
| `warnings` | array | 是 | 当前已知局限说明 |

## 五、节点契约

每个节点最少包含下面字段：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 节点唯一 ID，建议 kebab-case |
| `label` | string | 是 | 前端展示名称 |
| `type` | string | 是 | 节点类型；v1 先用 `concept` |
| `source_file` | string | 是 | 主要来源文件名 |
| `source_chunk_ids` | array | 是 | 对应证据块 ID |
| `weight` | number | 是 | 节点权重，供前端大小/优先级参考 |

### v1 允许但非必填

- `summary`
- `aliases`
- `domain`
- `color`

---

## 六、关系边契约

每条边最少包含下面字段：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 边唯一 ID |
| `from` | string | 是 | 起点节点 ID |
| `to` | string | 是 | 终点节点 ID |
| `label` | string | 是 | 前端显示的关系说明 |
| `relation_type` | string | 是 | 关系类型；如 `depends_on` / `part_of` / `related_to` |
| `weight` | number | 是 | 关系强度，范围 `0-1` |
| `source_file` | string | 是 | 主要来源文件名 |
| `source_chunk_ids` | array | 是 | 证据块 ID |

### v1 允许但非必填

- `bidirectional`
- `confidence`
- `note`

---

## 七、最小样例 payload

下面是 v1 最小样例的语义要求；物理样例文件见 `output/graph/graph-data-sample.v1.json`。

- 至少 `3` 个节点
- 至少 `2` 条边
- 至少覆盖 `Transformer / Attention / Multi-Head Attention` 这样一条可理解关系链
- 每个节点和边都要带证据字段，不能只有空标签

---

## 八、前后端消费约束

### 后端约束

1. 未满足这份结构时，不要把结果标记为正式图谱 payload。
2. 不要混用 `source_file` 和 `source_files` 两套字段名。
3. 节点和边的 `id / from / to` 必须稳定，不要每次请求随机生成。

### 前端约束

1. React 图谱组件只依赖这里的核心字段，不抢先要求复杂分析字段。
2. 节点渲染至少使用 `id / label / weight`。
3. 边渲染至少使用 `from / to / label / weight`。

## 九、验证方式

`S1-01` 过线，至少满足这 4 条：

1. 契约 Owner 文档已存在。
2. 最小样例 JSON 已存在。
3. `HANDOVER / ACTIVE_STATE / 蓝图 / DOCS_INDEX / 项目真值` 已能指向这份契约。
4. 后续执行者能只根据这份契约，维护 `/api/graph/data`、`/api/graph/extract` 与 React 图谱组件之间的数据边界。
