# AI知识库 — 知识卡片契约

> **用途**：固定 `S2-06 知识卡片` 的最小输入、输出和诚实边界
> **更新日期**：2026-05-12
> **性质**：当前项目专用 Owner，不替代 `PRD` 与长需求清单

---

## 一、这份契约先解决什么

- 先让 `S2-06` 从"想做概念卡片"变成一条可开工、可验证、可交接的最小闭环。
- 当前只承接 **基于已索引文件提取的概念卡片**，不冒充完整知识卡片管理系统。
- 知识卡片是图谱节点的"浓缩视图"：每个卡片展示一个概念的定义、来源、关联概念，方便快速浏览和跳转。

---

## 二、当前范围边界

### 当前支持

- 基于已索引文件批量生成知识卡片（复用图谱概念提取能力）
- 浏览所有已生成的知识卡片（支持搜索和排序）
- 查看单个知识卡片的详情（含来源文件、关联概念、定义摘要）
- 点击跳转到知识图谱页查看该概念在图中的位置

### 当前不冒充已有

- 不做卡片编辑/自定义（只读生成）
- 不做卡片分享/导出
- 不做卡片收藏/标注
- 不把"概念卡片"说成"知识管理系统"

---

## 三、数据存储契约

### 存储方案

JSON 文件，路径：`app/rag_app/data/knowledge_cards.json`

### 卡片结构

```json
{
  "attention_mechanism": {
    "concept_id": "attention_mechanism",
    "label": "注意力机制",
    "description": "一种让模型聚焦于输入序列中重要部分的机制",
    "source_files": ["transformer_basics.md", "deep_learning_intro.pdf"],
    "related_concepts": ["Transformer", "Self-Attention", "Multi-Head Attention"],
    "importance": 0.85,
    "card_type": "concept",
    "created_at": "2026-05-12T14:00:00",
    "updated_at": "2026-05-12T14:30:00"
  }
}
```

### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `concept_id` | `string` | 概念唯一标识，与图谱节点 id 对齐 |
| `label` | `string` | 概念显示名 |
| `description` | `string` | 概念定义/摘要（从索引内容中提取） |
| `source_files` | `string[]` | 来源文件列表 |
| `related_concepts` | `string[]` | 关联概念标签列表 |
| `importance` | `number` | 重要度 0~1（基于关联边数和出现频次） |
| `card_type` | `string` | 卡片类型：`concept` / `topic` / `method` |
| `created_at` | `string` | 首次生成时间（ISO 8601） |
| `updated_at` | `string` | 最近更新时间（ISO 8601） |

## 四、请求/响应契约

### 4.1 生成知识卡片

**Endpoint**：`POST /api/cards/generate`

**Request JSON**：

```json
{
  "source_mode": "auto",
  "max_cards": 20
}
```

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `source_mode` | `string` | 否 | `auto` | 数据来源：auto / live / sample |
| `max_cards` | `number` | 否 | 20 | 最多生成卡片数（2~50） |

**Response JSON**：

```json
{
  "status": "ok",
  "generated_count": 15,
  "total_cards": 15
}
```

### 4.2 查询知识卡片列表

**Endpoint**：`GET /api/cards`

**Query 参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `search` | `string` | 空 | 按概念名搜索 |
| `sort_by` | `string` | `importance` | 排序字段（`importance` / `label` / `updated_at`） |
| `limit` | `number` | 20 | 返回条数上限 |

**Response JSON**：

```json
{
  "cards": [
    {
      "concept_id": "attention_mechanism",
      "label": "注意力机制",
      "description": "一种让模型聚焦于输入序列中重要部分的机制",
      "source_files": ["transformer_basics.md"],
      "related_concepts": ["Transformer", "Self-Attention"],
      "importance": 0.85,
      "card_type": "concept",
      "created_at": "2026-05-12T14:00:00",
      "updated_at": "2026-05-12T14:30:00"
    }
  ],
  "total": 15
}
```

### 4.3 获取单个知识卡片

**Endpoint**：`GET /api/cards/{concept_id}`

**Response JSON**：

```json
{
  "concept_id": "attention_mechanism",
  "label": "注意力机制",
  "description": "一种让模型聚焦于输入序列中重要部分的机制",
  "source_files": ["transformer_basics.md", "deep_learning_intro.pdf"],
  "related_concepts": ["Transformer", "Self-Attention", "Multi-Head Attention"],
  "importance": 0.85,
  "card_type": "concept",
  "created_at": "2026-05-12T14:00:00",
  "updated_at": "2026-05-12T14:30:00"
}
```

**404 响应**：

```json
{
  "detail": "未找到概念 xxx 的知识卡片"
}
```

## 五、最小验收

1. `POST /api/cards/generate` 返回 `200`，生成至少 1 张知识卡片
2. `GET /api/cards` 返回 `cards` 数组和 `total` 计数
3. `GET /api/cards/{concept_id}` 返回单张卡片详情
4. 卡片的 `concept_id` 与图谱节点 id 对齐
5. 卡片的 `related_concepts` 来自图谱边关系
6. 前端页面能展示卡片网格和搜索
7. 不把"概念卡片"误报成"知识管理系统"
